## 需求 A：提词窗脱离浏览器，成为独立窗口

### A.1 现在是什么样

控制台里点「打开提词窗」，走的是 `web/console.js:473`：

```js
window.open('/prompter', 'prompter', 'width=1280,height=720');
```

就是一个**浏览器弹出窗口**。实际遇到的别扭：

- 窗口上沿有浏览器残留（看具体浏览器，有的还有标签栏/书签栏）
- 受浏览器缩放、快捷键、焦点策略影响 —— Ctrl+滚轮一下就改了整页比例
- 拖到第二块屏、全屏、置顶，全看浏览器心情
- F11 是**页面全屏**（浏览器自己的全屏），不是窗口全屏，退出路径也不一致
- 任务栏里它跟浏览器是一体的，切窗口时容易和"浏览器"混起来

**好消息**：提词窗的内容是纯前端（`web/prompter.*`），和后端只通过 WebSocket 通信。
换壳**不需要动后端任何逻辑** —— 这是这个需求能低成本做完的前提。

### A.2 三条备选路线

| | 做法 | 新增依赖 | 算不算独立窗口 | 工作量 | 风险 |
|---|---|---|---|---|---|
| **A1** Edge/Chrome `--app=` | 调 `msedge.exe --app=<url> --window-size=1280,720` | **无** | 半（无地址栏/标签栏，独立任务栏条目，但仍是浏览器进程） | 约半天 | 机器上得有 Edge 或 Chrome |
| **A2** pywebview + WebView2 | 用 WebView2 建真正的原生窗口 | `pywebview` + **系统要有 WebView2 运行时** | 是 | 2–3 天 | Win10 默认没有 WebView2；事件循环与 uvicorn 冲突 |
| **A3** Electron / Tauri | 打包一整个 Chromium | 100 MB+ | 是 | 1 周+ | 直接推翻「安装包 13 MB」这条取舍 |

### A.3 ⛔ 为什么暂时不选 A2

本机实测（也就是大多数用户的环境）：

```
系统      Windows 10.0.19045（Win10 22H2）
Edge      157.0.4341.60            ← 有
WebView2  C:\Program Files (x86)\Microsoft\EdgeWebView\Application\   ← 空
          %LOCALAPPDATA%\Microsoft\EdgeWebView\Application\           ← 也空
```

**Win11 自带 WebView2，Win10 不带。** 选 A2 就等于给 Win10 用户加一道前置安装：
要么装 Evergreen 引导器（约 2 MB，但要联网、要用户点同意），要么把固定版运行时
（约 130 MB）塞进安装包 —— 后者直接和「安装包越小越好」打架。

为了一个"窗口边框"付这个代价不划算。**先做 A1，A2 留作后续可选升级**
（真到那天，也是"检测到 WebView2 就用，没有就退回 A1"）。

### A.4 A1 的实现路径

**第 1 步 · 找浏览器**（新增 `app/win_window.py`）

按顺序找，找到第一个就用：
1. `%ProgramFiles(x86)%\Microsoft\Edge\Application\msedge.exe`
2. `%ProgramFiles%\Microsoft\Edge\Application\msedge.exe`
3. `%ProgramFiles%\Google\Chrome\Application\chrome.exe`
4. `%ProgramFiles(x86)%\Google\Chrome\Application\chrome.exe`
5. 注册表 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths\msedge.exe`

找不到就退回 `webbrowser.open(url)` —— **不能因为找不到浏览器就打不开程序**。

**第 2 步 · 起窗口**

```python
subprocess.Popen([
    exe,
    f"--app={url}",
    f"--window-size={w},{h}",
    "--disable-features=Translate,msEdgeSidebarV2",   # 别在本地应用里弹翻译/侧栏
], creationflags=0x08000000)   # CREATE_NO_WINDOW，别闪一个黑框
```

⛔ **不要加 `--user-data-dir`**。加了会生成一个几十 MB 的浏览器 profile 目录
（缓存、GPU 缓存、Service Worker），白白吃掉安装目录体积，又正好撞上需求 C 想要解决的
"越用越胖"。用默认 profile 就行 —— 本地 127.0.0.1 页面不存在隐私或会话问题。

**第 3 步 · 让控制台能触发它**

JS 没法启动进程，所以加一个接口：

```
POST /api/open_prompter   → {"ok": true, "via": "edge-app" | "browser"}
```

`console.js` 里把 `window.open(...)` 换成先调这个接口，**接口失败再退回 `window.open`**
（比如后端被防火墙挡了、或者用户在别的机器上开）。

**第 4 步 · 控制台自己也用 app 模式**

`run.py` 里 `_open(url)` 现在走 `webbrowser.open`，改成同一套逻辑：
开机时控制台也以 app 窗口打开。这样"脱离浏览器"是**整体成立**的，
而不是只有提词窗特殊。

> 保留一个开关：`ui["app_window"]`（默认 `true`）。有人就是想用浏览器 + 扩展
> （比如录屏插件），得让他能退回去。设置页放一个勾选框。

### A.5 这一步刻意不做的

- **不做无边框 + 自绘标题栏**。Edge app 窗口自带一条细标题栏，反而好拖拽、好关。
- **不做置顶（always on top）**。Edge 命令行没有可靠的置顶参数；要做就得走 Win32
  `SetWindowPos(HWND_TOPMOST)`，得先按标题/进程找到那个窗口 —— 留到 A2 再做。
- **不做多窗口管理**。程序本来就只需要"一个控制台 + 一个提词窗"。

### A.6 验收

- 点「打开提词窗」→ 出来一个**没有地址栏、没有标签栏**的窗口，任务栏有独立条目和图标
- 窗口能拖到第二块屏、能 F11 全屏、空格/Esc/滚轮照常
- 关掉提词窗，服务和录音状态不受影响
- 把 `ui["app_window"]` 关掉 → 回到浏览器窗口，功能一样
- 找 Edge 路径失败时（临时改名目录模拟）→ 自动退回 `webbrowser.open`，不报错
- `--fast` 测试全过

## 需求 B：限制 AI 跟读的跳跃幅度

### B.1 现在为什么会大幅上下跳

`app/align.py:138-139` 决定每一拍的搜索窗口：

```python
lo = max(0, self.pos - self.lookback)          # lookback  = 40 字
hi = min(n_chars, self.pos + self.lookahead)   # lookahead = 100 字
```

`config.py` 的 `ALIGN` 里就是 `{"lookback": 40, "lookahead": 100, ...}`。
半全局 DTW 在这个窗口里找**代价最小**的位置，而且**终点自由** ——
所以一次更新最远能往前跳 **100 字**。

按默认 14 字/行算，100 字 ≈ **7 行**。再叠上 `motion.py` 的平滑（`tau_fwd = 0.09 s`），
0.3 秒内滑过 7 行，肉眼看就是"唰"地蹿出去。

**重复上下文是主要触发条件**：稿子里同一句话出现两三次时，DTW 在后面那个位置
算出来的代价一样低（甚至更低），于是锁到远处；下一拍又锁回来 —— 来回几次
就是用户说的"上下滚动，偏离正在读的地方"。

### B.2 修法：限「单次位移」，不是限「搜索窗口」

⚠️ **不要靠把 `lookahead` 调小来解决。** 100 字是留给"正常语速下 4 秒能念多少字"的
余量，压下去正常跟读会掉队 —— 从一个毛病换成另一个毛病。

要限的是**一次更新允许移动多远**。在 `align.py` 的 `update()` 里，
算出 `new_pos` 之后、写进 `self.pos` 之前夹一次：

```python
limit = self.max_jump_lines * self.script.per_line      # 0 = 不限制
if limit > 0:
    new_pos = max(self.pos - limit, min(self.pos + limit, new_pos))
```

⛔ **必须夹在 `Aligner` 内部，不能在 `session.feed_asr()` 里夹。**
因为 `self.pos` 同时是**下一拍的搜索窗口锚点**：在 session 里夹，aligner 内部还停在
远处，下一拍会绕着一个"到不了的位置"算窗口，越算越偏，反而更容易乱跳。

其余几个关键点：

- `Script` 已经有 `per_line`（`app/script.py:129`），不用新传参
- `max_jump_lines = 0` 时**行为与 v2.2.4 完全一致**（向后兼容，也是"不限"这一档的语义）
- **滚轮不受影响**：`session.wheel()` 本来就会 `aligner.reset()` 把锚点挪到新位置，
  所以人工跳转不经过这个夹子。这点很关键 —— 否则用户想跳到后一段就跳不过去
- 夹子只夹"这一拍能动多远"，连续几拍照样能挪很远（3 Hz × 5 行 × 14 字 ≈ 210 字/秒），
  所以**真正的跳读只是从"瞬移"变成"快速滑过去"**，不会卡住

### B.3 参数与界面

`config.py` 的 `DEFAULT_UI` 新增三个键：

```python
"max_jump_lines": 5,
"max_jump_lines_min": 0,
"max_jump_lines_max": 50,
```

- 控制台加第 5 个滑块。现有 4 个在 `web/console.html:46-49`，照抄 `rPer` 的写法即可
- 文案：`最大跟进 <output> 行`；值为 0 时显示 **`不限`**，不要显示"0 行"（读不通）
- **只在准备态可调**：沿用 `console.js:89` 那句 `rCps.disabled = ai || runState !== 'IDLE'`
  的同一套规矩。录制中锁死，和字号 / 每行 / 红线 / 速度一致
- 落盘走 `data/state.json` 的 `ui` 段

> **老配置不用担心**：`store.py:31-32` 是 `ui = dict(DEFAULT_UI); ui.update(保存的值)`，
> 新键自动补默认值，老 `state.json` 读进来不会 KeyError。

### B.4 默认 5 行，不是 3 行

你提的合理区间是 3–5 行。**默认取 5**，因为：

- 念得快的时候一拍（0.3 s）真能推进 4–6 行，默认 3 会频繁"被拽住"，手感更差
- 5 行已经是"肉眼能跟上的滑动"，足以压掉 7 行的突兀感
- 真想紧的人自己往下调 —— 滑块就是干这个的

**不建议默认 1 或 2**：那会让正常语速都变得一顿一顿，用户会以为是卡顿。

### B.5 验收

- 造一段**重复上下文**的稿子（同一句出现 3 次、间隔 40–100 字），朗读时位置不再暴跳
- 滑块调到 1 行：跳读时位置一格一格挪，不是瞬移
- 滑块调到 0：行为和 v2.2.4 一致
- 正常语速（约 4 字/秒）跟读不掉队、不顿
- 滚轮仍然能一次跳很远（人工接管优先）
- 新增 `tests/test_align.py` 用例：给定 `pos=100`、识别结果匹配到 190 字处、
  `max_jump_lines=5`、`per_line=14` → 结果必须 ≤ `100 + 70`

## 需求 C：运行时文件与自动清理

### C.1 先回答你的担心：没有真正的临时文件，但有一处会无限长

把仓库里所有写盘的位置全查了一遍（`grep -rn "open(|write_text|tempfile" app/ run.py`）：

| 位置 | 写什么 | 会不会越长越大 |
|---|---|---|
| `data/scripts/*.md` | 你的稿件 | 只随稿件数量增长 —— **这是你的资产** |
| `data/state.json` | 界面设置 | 每次覆写，不增长（几百字节） |
| **`data/launch.log`** | **每次启动追加一段**（约 500 B/次） | ⚠️ **只追加，永不轮转** |
| **`%TEMP%\AITeleprompter-launch.log`** | 同上（装到不可写目录时的退路） | ⚠️ 同上 |
| `app/__pycache__/` | Python 字节码 | 有界（跟源码走，几 MB） |
| 安装目录 `_tmp/`、`is-*.tmp` | Inno 安装过程的中间物 | 装完不一定清干净（实测见过残留 4.4 MB 的 `is-*.tmp`） |

**结论：程序里没有用 `tempfile`，不录 WAV，不缓存音频。** 麦克风数据全在
`listener.py` 的环形缓冲里（内存），所以不存在"录一次多一堆文件"。
这一点可以放心 —— 你现在感觉不到膨胀，是因为真的没有。

**但 `launch.log` 确实是个漏水点。** 目前每次启动追加约 500 B（含解释器路径、
Python 版本、控制台有无），异常时还会追加完整 traceback（几 KB）。
一年几百次启动 ≈ 100–300 KB，不会撑爆，但**它会永远长下去，而且没有任何上限**。
这就是你担心的那件事，只是它长得很慢，不该被忽略。

### C.2 修法

**① `launch.log` 启动时轮转**（`run.py` 的 `_ensure_streams`）

打开之前先看大小，超过 **512 KB** 就 `launch.log` → `launch.log.1`（直接覆盖旧的
`launch.log.1`），再新建一个空的。**只留一份**，总占用上限 ≈ 1 MB。

`run.py:384` 那个崩溃分支（`except BaseException` 里再写一遍文件）要**复用同一个函数**，
别各写一套 —— 现在这两处逻辑是复制粘贴的，加轮转时漏一处就等于没加。

⛔ 轮转顺序：**先 rename，再 open("a")**。反过来的话 Windows 上文件正被自己占着，
rename 会失败（`PermissionError`），然后被 `except OSError` 吞掉，看起来"没效果"。

**② `%TEMP%` 那份同样轮转**，同一段逻辑，别写两遍。

**③ 控制台加「数据占用」面板**（设置页）

一行一行列出来，让人一眼看清是谁胖了：

```
稿件        4 篇      11.8 KB
日志        2 个       1.0 MB      [清理日志]
语音模型    1 个       1.8 GB
本次安装     —        6.9 GB
```

- 只统计、只显示，**不自动删任何东西**
- 「清理日志」只删 `*.log` / `*.log.1`，**永不碰 `data/scripts/`**
- 这个面板也顺便解决"用户不知道模型占多大"的老问题（README 里只能写死 1.8 GB）

**④ 安装器残留**

`AI提词器.iss` 的 `[Run]`/收尾阶段删掉 `_tmp\` 与 `is-*.tmp`。
`run.py` 启动时也顺手清一次（双保险）—— 清不掉就算了，绝不能因此起不来。

**⑤ `__pycache__` 不动**

删了下次启动还要重新编译，纯亏。它的大小跟着源码走，有界，属于正常现象。

### C.3 明确不做的（划边界）

- **不自动删 `data/scripts/*.md`**。那是用户资产，误删一次就够致命，没有"清理稿件"这种功能
- **不做定期清理任务**（计划任务 / 常驻服务）。为 1 MB 日志引入一个后台进程不值得
- **不把日志写到用户看不见的地方**。出问题时它是唯一线索，"眼不见为净"等于把排障能力删了

### C.4 验收

- 连续启动 30 次，`data/launch.log` 在 512 KB–1 MB 之间震荡，不再单调增长
- 故意让启动崩一次（临时改坏一个 import），崩溃栈**完整**写在日志里 ——
  轮转不能把崩溃记录卷走
- 「数据占用」面板的数字与 `du` 实测一致（误差 < 5%）
- 点「清理日志」后日志文件消失，稿件一篇不少
- 卸载仍然单独询问稿件与模型，默认「否」

## 优先级与发布节奏

| 顺序 | 需求 | 版本 | 理由 |
|---|---|---|---|
| 1 | **C 磁盘卫生** | 一起进 **2.3.0** | 改动最小、纯收益、不碰交互逻辑 |
| 2 | **B 跳跃限制** | 一起进 **2.3.0** | 有新增 UI 和配置项，用户能直接感知 |
| 3 | **A 独立窗口** | **2.4.0** | 要改进程启动方式和安装器依赖，单独一版好回滚 |

**为什么 C 和 B 合成一个版本**：一个治文件、一个治体验，互不干扰，但都要碰
`config.DEFAULT_UI` 和 `data/state.json` —— 一起测一轮比发两次省事。
而且它们都能用 `--fast` 测试覆盖，不需要真装一遍。

**为什么 A 单独走**：它改的是"程序怎么被启动"，出问题会直接表现为"点不开"。
和 B/C 混在一个版本里，回滚时会把两个已经验证好的功能一起退掉。

### 每个版本的最小动作

```bash
# 2.3.0
python tests/run_all.py --fast        # 194 项，新增用例要在这里面
python tools/build_installer.py --version 2.3.0
# 发版流程见 v2.0 文档 §17（含 ⛔ Release 附件名只能用 ASCII，见 §17.7）

# 2.4.0
# 同上，另加：在【没装 WebView2 的机器】上验一遍（本机就是，正好）
```

## 共同的验收底线

三条都要满足，缺一条就不发：

1. `python tests/run_all.py --fast` **194 项全过**，新增参数要有测试
2. 老 `data/state.json`（没有新区段）读进来不报错 —— `store.py` 的 `dict(DEFAULT_UI)`
   会补默认值，但**新代码必须用 `ui.get("key", 默认值)` 而不是 `ui["key"]`**，
   防止将来哪天有人绕过 `store.py` 直接构造 `ui`
3. 极端环境不崩：**没装 WebView2**、**没有麦克风**、**空稿件**、**只读安装目录**
   —— 这四个是本项目历史上真出过问题的地方

## 附：三条需求之间的相互影响

写在最后，因为很容易被忽略：

- **A × C**：如果哪天给 Edge 加了 `--user-data-dir`，就会凭空多出一个几十 MB 的
  浏览器 profile 目录。所以 A 的实现里**明确不加这个参数**；哪天真要加，
  必须同时把它纳入 C 的清理面板
